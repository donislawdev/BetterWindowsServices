// Win32 surface used by this project. CsWin32 turns each name into a P/Invoke at
// build time, so nothing here becomes a runtime dependency (ADR-2, ADR-15).
//
// Keeping the list explicit is deliberate: it is the honest inventory of what the
// tool touches in the operating system, and it belongs under review like any other
// contract.

// Service control manager: opening, enumerating, reading configuration.
OpenSCManager
OpenService
CloseServiceHandle
EnumServicesStatusEx
QueryServiceConfig

// The delayed start flag is not part of the configuration structure above. The manager
// reports start type 2 for a delayed entry and for an ordinary automatic one alike, so
// telling them apart takes a second call at a different information level.
//
// Trigger information comes through the same call at yet another level. Nothing else
// exposes it - services.msc does not show it at all, which is why the specification calls
// it the strongest thing in the details panel.
QueryServiceConfig2

// Writing one field of that configuration - the start type, and nothing else. Arriving
// 2026-08-25 with the first ask in this product that changes a setting rather than moving a
// service. Every other field of the call is handed SERVICE_NO_CHANGE, which is the manager's
// own way of saying "leave that one alone" - a tool that rewrote a binary path because it was
// passing the whole structure would be the quietest possible way to break a machine.
ChangeServiceConfig

// And the late start flag beside it, since 2026-09-24 (backlog 231, route (c)). It is written
// at the one information level SERVICE_DELAYED_AUTO_START_INFO, which is already asked for above
// for reading, so the call cannot touch anything else. Every startup setting writes it - the
// way sc.exe does, measured on the throwaway machine that day - and an entry in a load order
// group refuses it with 87, which the plan says before anybody presses.
ChangeServiceConfig2

// What the entry is allowed to do, and who is allowed to do things to it.
//
// The privileges and the service SID type ride on the configuration handle the listing
// already holds, at two more information levels of the call above. The descriptor does
// not: it needs READ_CONTROL, which is a different right, so it takes a handle of its own.
//
// That separation is measured rather than tidy. Under a restricted token on 2026-08-01,
// five entries of 810 - LSM, NetSetupSvc, pla, QWAVE and QWAVEdrv - open for configuration
// and refuse when READ_CONTROL is added to the same request. Asking for both at once would
// have taken the start type, the account and the launch path away from entries that report
// them today, in exchange for a field they were never going to give up.
//
// The SACL is deliberately not read. Asking for it fails the whole descriptor with error 5
// unless SeSecurityPrivilege is enabled, which it is not even in an elevated session, so
// including it would trade owner, group and DACL for nothing.
QueryServiceObjectSecurity

// Who breaks if this one stops. The manager answers this itself, and its answer is worth
// more than inverting the declared dependencies would be: an entry can declare a load
// order group rather than a service, and only the manager knows who is in that group.
//
// Measured 2026-08-01: sc.exe enumdepend truncates its own output to three entries and
// exits with ERROR_MORE_DATA without retrying, so it is not usable as a comparison
// authority. The API itself is fine when asked for the size first.
EnumDependentServices

// Carrying a plan out. These three are the only calls in the project that change
// anything, and they are deliberately listed together: this short block is the whole
// answer to "what can this tool do to my machine".
//
// Asking is not the same as arriving. Both calls return once the manager has taken the
// request, and the entry then works its way to the state through START_PENDING or
// STOP_PENDING. Knowing when it got there takes the third call, asked repeatedly.
StartService
ControlService
QueryServiceStatusEx

// Ending a process, which is the fourth of those and the only one that asks nobody's permission.
//
// THE SENTENCE THIS FILE MAKES ABOUT ITSELF CHANGED ON 2026-09-06 AND IS REWRITTEN RATHER THAN
// LEFT STANDING. The block above says these calls are the whole answer to "what can this tool do
// to my machine", and that answer used to be "ask the manager to move things". It now includes
// one line that ends a process outright, taking every other service living in that process with
// it. `C3` of the specification asked for it from the start and the owner settled its shape that
// day - the point of writing it here is that a reader of this file should not have to find that
// out from anywhere else.
//
// OpenProcess is already on this list for reading memory, and PROCESS_TERMINATE is already a
// member of the rights enumeration below. What was missing was the verb, and the verb is the
// whole of what changed.
TerminateProcess

// How much memory the process behind an entry is using.
//
// The only block here that leaves the service control manager entirely: memory belongs to
// a process, so this asks the process. Read-only, and the access right below is the whole
// reason this is safe to say - PROCESS_QUERY_LIMITED_INFORMATION cannot read, write or
// touch anything in the process, it only allows asking about it.
//
// Which right, measured rather than taken from the first sentence of the documentation.
// GetProcessMemoryInfo is documented as needing PROCESS_QUERY_INFORMATION and
// PROCESS_VM_READ, and separately as accepting PROCESS_QUERY_LIMITED_INFORMATION since
// Windows 7. Those are not equivalent in practice: over the 110 processes behind services
// on 2026-08-01, the limited right was refused by none and the wider pair by seven -
// lsass, MsMpEng, MpDefenderCoreService, NisSrv, SecurityHealthService and two svchosts.
// Asking for more than is needed costs answers and looks exactly like a bug.
OpenProcess
GetProcessMemoryInfo
PROCESS_MEMORY_COUNTERS_EX
PROCESS_ACCESS_RIGHTS

// When a process started, which is here as an IDENTITY rather than as anything a person reads.
//
// Windows hands out process numbers again once a process is gone, so the number in a preview can
// belong to something else by the time the plan runs. The pair of number and creation time is the
// nearest thing to an identity Windows will give out, and this is the half that is not the number.
// It is read while the plan is built and read again on the handle that does the ending, so the
// check and the ending share one handle and nothing can slip between them. Backlog 323.
//
// The right, measured rather than taken on trust. The documentation says this accepts
// PROCESS_QUERY_INFORMATION or PROCESS_QUERY_LIMITED_INFORMATION, and what the documentation
// cannot say is whether a machine GRANTS the narrower one. Counted on 2026-09-08 over 186
// processes behind services on two machines: refused zero times, including by all eleven processes
// Windows was protecting, and the call answered on every one of them.
// The times themselves are NOT on this list, and that is the generator's decision rather than an
// omission: it hands them over as the framework's own file time instead of a Win32 one. Worth
// saying here because this list is meant to be the inventory - a reader looking for the structure
// beside the call should know it is not missing.
GetProcessTimes

// Who signed the file an entry runs, and whether the system trusts that signature.
//
// Read-only, and the whole block is about files rather than services - none of it can
// change anything. It is long because Windows signs its own binaries two different ways
// and only one of them can be answered by looking at the file.
//
// Measured 2026-08-01 over 544 distinct files: asking WinVerifyTrust about the file alone
// answers 346 of them and comes back TRUST_E_NOSIGNATURE for 198, of which the system
// itself trusts 189. Those are catalogue signed - the signature lives in a separate
// catalogue file and is found by hashing the binary and looking the hash up. Skipping that
// path would report 189 files as unsigned while Windows trusts them, which is the same
// class of confidently wrong answer as checking a raw image path against the disk.
WinVerifyTrust
WINTRUST_DATA
WINTRUST_FILE_INFO
WINTRUST_CATALOG_INFO
WINTRUST_ACTION_GENERIC_VERIFY_V2

// The catalogue path: hash the file, find the catalogue holding that hash, then verify
// against the catalogue rather than against the file.
CryptCATAdminAcquireContext2
CryptCATAdminReleaseContext
CryptCATAdminCalcHashFromFileHandle2
CryptCATAdminEnumCatalogFromHash
CryptCATAdminReleaseCatalogContext
CryptCATCatalogInfoFromContext
CATALOG_INFO

// Who the signer is does NOT need anything here, and that is worth saying rather than
// leaving as an absence. The obvious route reads the certificate back out of the state the
// verification leaves behind, which costs four more functions and a struct that CsWin32
// hands over in two incompatible shapes. The standard library already reads a certificate
// out of a signed file, and for a catalogue-signed binary the signer is whoever signed the
// catalogue - whose path the calls above already produced. Same answer, four fewer entries
// on this list.

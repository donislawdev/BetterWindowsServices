คู่มือ

บริการตัวไหนควรทำงาน

คำตอบที่ตรงไปตรงมาคือไม่มีใครบอกคุณได้ และทุกรายชื่อที่อ้างว่าบอกได้กำลังอธิบายเครื่องที่ไม่ใช่ของคุณ สิ่งที่ตอบได้แคบกว่าและมีประโยชน์กว่ามาก: อะไรบนเครื่องนี้ที่ไม่ลงตัว และอะไรต่างจากตอนที่มันยังใช้งานได้

ทำไมคำถามทั่วไปจึงไม่มีคำตอบ

  • ชุดของบริการต่างกันตามรุ่น เวอร์ชัน และบทบาทของ Windows โดเมนคอนโทรลเลอร์ แล็ปท็อป และโฮสต์คอนเทนเนอร์ไม่เหมือนกันในแทบทุกเรื่อง และรายชื่อที่เขียนไว้สำหรับอย่างหนึ่งผิดสำหรับอย่างอื่น
  • ครึ่งหนึ่งของสิ่งที่ติดตั้งไม่ได้มาจาก Windows ไดรเวอร์ เอเจนต์ บริการอัปเดต เดมอนใบอนุญาต ทุกตัวถูกบางอย่างวางไว้ที่นั่น และไม่มีรายชื่อทั่วไปที่รู้ว่าอะไร
  • บริการส่วนใหญ่ตั้งใจให้หยุดอยู่ Windows สมัยใหม่เริ่มแค่เศษเสี้ยวของสิ่งที่ลงทะเบียน ที่เหลือรอทริกเกอร์ อุปกรณ์มาถึง พอร์ตเปิด การเข้าร่วมโดเมน และหยุดคือสถานะที่ถูกต้องของมัน
  • รายชื่อ “ปิดสิ่งเหล่านี้เพื่อประสิทธิภาพ” คือวิธีที่เครื่องพัง บริการที่ดูเหมือนว่างคือตัวที่มีบางอย่างเริ่มตามความต้องการ และความล้มเหลวปรากฏหลังจากนั้นหนึ่งสัปดาห์ในที่ที่ไม่เกี่ยวข้อง

คำถามที่มีคำตอบ

อะไรที่ควรทำงานแต่ไม่ได้ทำงาน

start:auto !status:running

Windows ถูกสั่งให้เริ่มสิ่งเหล่านี้และพวกมันไม่ได้ทำงาน บนเครื่องที่แข็งแรงนี่คือรายชื่อสั้นๆ รายการสองสามตัวที่เริ่มช้าแล้วหยุดอีก อย่างอื่นก็ควรดูสักหน่อย

อะไรที่ปิดใช้งานแต่ยังทำงาน

mismatch:running

การกำหนดค่าและสถานะขัดแย้งกัน มักเป็นเพราะมีคนปิดใช้งานมันโดยไม่ได้หยุด และการรีสตาร์ตครั้งถัดไปจะเป็นเรื่องแปลกใจ

อะไรที่ชี้ไปยังไฟล์ที่หายไป

file:missing

การถอนการติดตั้งที่ทิ้งการลงทะเบียนไว้ ไม่เป็นอันตรายจนกว่าจะมีอะไรพยายามเริ่มมัน และเป็นเบาะแสว่าเคยมีอะไรอยู่บนเครื่องนี้

อะไรที่ไม่มีใครลงลายเซ็น

signed:no peruser:no

ไม่ใช่หลักฐานของอะไรด้วยตัวเอง และเป็นที่ที่เหมาะจะเริ่มอ่าน คำค้นที่สองตัดตระกูลต่อผู้ใช้ออก ซึ่งไม่เช่นนั้นจะทำให้รายชื่อเต็มไปด้วยรายการที่เกือบซ้ำกัน

อะไรที่ขอสิทธิพิเศษที่แรงที่สุด

privilege:SeDebugPrivilege

สิทธิพิเศษที่ให้กระบวนการเปิดกระบวนการอื่นได้ทุกตัว บริการที่ถูกต้องไม่กี่ตัวขอมัน และควรรู้ว่าตัวไหนบนเครื่องของคุณที่ขอ

อะไรที่กำลังรอทริกเกอร์

trigger:any status:stopped

หยุดอยู่เพราะยังไม่มีอะไรขอพวกมัน ไม่ใช่เพราะมีบางอย่างผิด การรู้ว่าตัวไหนเป็นแบบนี้คือวิธีที่รายชื่อแรกหยุดน่าตกใจ

อันที่ชนะทุกอย่าง

ถามเครื่องเอง ตอนที่มันยังใช้งานได้

สร้างสแนปช็อตในวันที่เครื่องเข้าสู่การใช้งาน แล้ว สิ่งนี้ควรทำงานไหม จะกลายเป็น สิ่งนี้ทำงานตอนที่ทุกอย่างปกติไหม คำถามเกี่ยวกับเครื่องของคุณ ไม่ใช่เกี่ยวกับเครื่องในบทความ

bws snapshot create C:\baselines\web01.json --note "after the build"
# ... หนึ่งสัปดาห์ แพตช์ หรือเหตุการณ์ผ่านไป
bws snapshot diff C:\baselines\web01.json --live

การกำหนดค่ารายงานแยกจากสถานะการทำงาน คำตอบจึงไม่ใช่บริการสี่สิบตัวที่บังเอิญทำงานอยู่ แต่เป็นประเภทการเริ่มต้นที่ใครสักคนเปลี่ยน

ตรวจสอบดริฟต์ของเครื่อง

ก่อนจะหยุดอะไร

ทุกการหยุดในเครื่องมือนี้แสดงแผนก่อน: ขั้นตอน สิ่งที่ล้มตามไปด้วย และคำเตือนเมื่อหนึ่งในนั้นเป็นสิ่งที่เครื่องทำงานไม่ได้ถ้าไม่มี รายชื่อของสิ่งเหล่านั้นเป็นรายชื่อตั้งต้น 7 ตัว ได้แก่ RPC สองส่วนและตัวเปิด DCOM ตัวจัดการบัญชี การแยกคีย์ ตัวจัดการเซสชัน และ plug and play และ รีโมตเดสก์ท็อปไม่อยู่ในนั้น ดังนั้นเมื่อทำผ่านเซสชันระยะไกล ให้อ่านแผน

ดาวน์โหลดสำหรับ Windows ทุกฟิลด์ที่คุณถามได้

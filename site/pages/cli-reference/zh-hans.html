每个命令做什么

list 和 show

list 是整台计算机，由 --query 缩小范围。show 是单个条目及其所有已知信息：签名、特权、安全描述符和内存，每次都会全部读取，因为针对一个条目只需约六十毫秒，而针对整台计算机则需要一秒。真正为空的字段会被省略，除非你传入 --full。无人能读取的字段无论如何都会被打印，因为省略它会看起来像一个答案。

stop、start 和 restart

每个都会生成计划并执行。--dry-run 打印计划而不做任何更改，--dependents 把会受影响的服务作为独立的步骤放进计划，--timeout 指定一个步骤可以在没有进展的情况下持续多久。驱动程序会被拒绝而不是尝试，因为停止内核驱动程序往往不重启就无法恢复。

kill：用于停不下来的服务

它会请求服务停止，只有在无效时才结束它背后的进程，所以自己能停止的条目绝不会被强行结束。结束一个进程会带走该进程中的所有其他服务，不论它们是否事先已经停止，预览会点出它们的名称，并按编号指出该进程。--force 跳过礼貌的那一步，预览于是显示一个步骤而不是两个。--restart 随后把一切带回来。

Windows 对这个想法的表述不同。Stop-Service 上的 --force 的意思是“即使有东西依赖它”，这在这里是 --dependents 的作用。这就是它是一个独立命令、而不是 stop 上的一个选项的原因。

start-type：是一项设置，而不是一次操作

它指明服务管理器在下次启动时如何处理某个条目，没有 --stop 时它不会移动任何东西：正在运行的条目继续运行，已停止的保持停止，计划会这样说明。disabled 值得停下来想一想，因为它会让服务管理器根本不再启动该条目，包括按需为其他需要它的东西启动。delayed 是自动，比其他自动条目稍晚启动：在查询中 start:delayed 询问的就是这个词。Windows 会拒绝把它用于属于加载顺序组的条目，计划会在任何操作发生之前说明这一点。四种类型都会像 sc.exe 那样记录该条目是否延迟启动。--stop 只能与 disabled 搭配，在写入设置之后，在同一份计划中停止该条目。

snapshot create 和 snapshot diff

create 始终会读取签名和哈希，因为快照是要保存下来、之后再比较的，没有它们的快照与有它们的快照比较时，会让人觉得计算机发生了变化。diff 说明从第一个文件到第二个文件，或用 --live 从一个文件到这台计算机，发生了哪些变化。快照页面介绍了格式和理由。

history：谁改的，来自 System 日志

从 System 日志中读取启动类型更改和安装记录，最新的在前，带有 Windows 记录的账户。第一行说明日志能追溯多远、是否被清除过，因为历史记录的长度只取决于日志。带上名称时，显示的是该服务的启动类型更改：安装记录只在不带名称时列出，因为 Windows 记录安装时用的是显示名称，而从不是服务名称。账户在这台计算机能自行解析其名称时显示名称，否则显示其 SID，启动类型则使用 Windows 所写的词。

tool：针对常见问题的现成答案

与窗口在 Tools 选项卡上显示的工具相同。bws tool 列出它们，bws tool fix 列出快速修复：printer、sound、indexing 和 search，每一项都是重启一个 Windows 服务连同依赖它的内容，之所以选它们，是因为 Microsoft 自己的故障排除页面就是这样建议的。bws tool fix printer 就是 bws restart Spooler --dependents：相同的计划、相同的输出和相同的退出代码，而且和这里每个会更改内容的命令一样，它不会先询问，所以想在运行前查看，请使用 --dry-run。

license：你下载的文件里有什么

它什么也不读取，既不读服务管理器，也不读磁盘和网络，而是从编译进可执行文件的登记表中回答。--components 会把通知变成每个组件及其版本、许可证和来源。这与随下载一同发布的物料清单所含的集合相同，因为两者都由同一份登记表生成，这也是值得拥有它的原因：程序是一个自包含的文件，所以它旁边没有任何东西可供扫描程序读取。

bws show Spooler --full                        也包括真正为空的字段

先看，再更改

bws restart Spooler --dry-run                只显示计划，不做别的
bws restart Spooler --dependents             连同依赖它的内容一起重启
bws stop Spooler --dependents --timeout 120  允许每个步骤在没有进展的情况下持续两分钟
bws start-type WSearch delayed --dry-run     比其他自动条目稍晚启动
bws start-type Spooler disabled --stop       在一份计划中禁用并停止它

停不下来的服务

bws kill Spooler --dry-run          进程，以及同在其中的每个服务
bws kill Spooler --restart          只有停止失败时才结束进程，然后把一切带回来
bws kill Spooler --force --dry-run  一步而不是两步：立即结束进程

快照与漂移

bws snapshot create before.json --note "before the patch"  冻结计算机，并在其中保留一条备注
bws snapshot diff before.json after.json                   两个文件：相隔两天，或两台计算机
bws snapshot diff before.json --live                       把文件与这台计算机的当前状态对比
bws snapshot diff before.json --live --exit-code           同上，若配置发生漂移则以 5 结束

谁改的

bws history          System 日志中保存的每一次启动类型更改和安装

bws history --json   同样的内容，作为文档，含日志和更改

在 PowerShell 脚本中

# 应该在运行却没有运行的条目，作为对象
bws list --query "start:auto !status:running" --json | ConvertFrom-Json | Select-Object serviceName, displayName, status

# 未签名的文件，写入电子表格
bws list --query "signed:no" --json | ConvertFrom-Json | Select-Object serviceName, binaryPath | Export-Csv unsigned.csv -NoTypeInformation

# 一个服务需要什么
(bws show Spooler --json | ConvertFrom-Json).dependsOn

# 根据退出代码分支的夜间检查
bws snapshot diff C:\baselines\web01.json --live --exit-code > $null
switch ($LASTEXITCODE) {
  0 { 'no configuration drift' }
  5 { 'the configuration drifted' }
  default { "no clean answer, exit code $LASTEXITCODE" }
}

退出代码

共 {{exit_code_count}} 种结束方式，每一种对脚本来说都是不同的处理。数据输出到标准输出，其余所有内容输出到标准错误，因此 bws list --json | jq 可以正常工作，警告也绝不会混进你的 JSON。

每个 JSON 文档都是纯 ASCII：ASCII 之外的字符会被写成六个字符的转义序列，所有 JSON 读取器都会把它还原成那个字符，所以 bws list --json > file.json 是有效的 UTF-8，而 | ConvertFrom-Json 无论控制台设置为什么代码页都能正确读取。在供人阅读的文本中，会移动终端而不是被打印出来的字符，例如制表符、换行、转义序列和方向覆盖字符，会显示为它的码位 <U+001B>。

-- 表示选项到此结束，所以名称以短横线开头的服务仍然可以指定：bws show -- -odd。工具交给你的命令行是为 PowerShell 编写的：带空格的名称放在双引号中，cmd 对其读取方式相同，而 PowerShell 会在双引号内展开的名称，例如 MSSQL$SQLEXPRESS，则放在单引号中。

{{table:exit-codes}}

Ctrl+C 有三个级别，每一级都说明下一级的代价。第一级停止继续前进，并仍会把已取走的东西放回去，第二级让现状保持原样，并仍会打印报告，第三级结束进程。手动停止的运行即使每个步骤都已完成，也会以 4 结束。

关闭控制台窗口算作第一次 Ctrl+C。此后 Windows 会给程序五秒钟，在这段时间内它会停止前进，并把它关掉的东西放回去。注销和关机会在没有任何它能作出反应的警告的情况下结束它，断开的远程会话也可能如此。

在计划任务中

这个工具为之而生的形态：在计算机已知良好时把它冻结，然后每晚询问它是否仍然如此。

# 计算机投入使用的那一天
bws snapshot create C:\baselines\web01.json --note "after the build"

# 每晚，通过计划任务
bws snapshot diff C:\baselines\web01.json --live --exit-code --json > C:\logs\drift.json
#   0 - 没有配置漂移
#   5 - 配置发生了漂移，drift.json 会说明具体内容
#   3 - 已运行但无法读取全部内容，因此答案是部分的

窗口的参数

BetterWindowsServices.exe 接受一个供人使用的参数：--catalogue 会打开一张开发者用的表，显示窗口的每个组件在每种状态下的样子，并且不会从你的计算机读取任何内容。第二个参数 --carry 是窗口把它正在显示的内容交给它以管理员身份重新启动的自己的副本的方式。没有人会手动输入它，其中任何该窗口不可能写出的内容都会被拒绝。

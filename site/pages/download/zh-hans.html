发布内容

文件说明
{{archive_window}}窗口：BetterWindowsServices.exe，一个自包含的可执行文件，内置自己的 .NET 运行时
{{archive_cli}}命令行：bws.exe，一个自包含的可执行文件，用于脚本、计划任务和 CI
{{archive_installer}}安装程序：为计算机上的每个账户把这两个程序安装到 Program Files，窗口出现在开始菜单中，bws 加入计算机的 PATH

可以取其一或两者都要，它们是同一引擎的两个客户端，彼此互不依赖。在服务器上，命令行是两者中较小的一个，窗口能做的它都能做。

安装程序包含的内容与两个压缩包完全相同。它可以用 msiexec /i {{archive_installer}} /qn 静默安装，较新的版本会覆盖安装在较旧的版本之上，并且它不会关闭任何正在运行的程序，所以升级前请先关闭窗口和任何正在运行的 bws，因为遗留在运行中的副本可能会报错停止。在“设置”的“应用”中卸载，会删除程序、开始菜单项和 PATH 项，而不会动你自己的文件。

可执行文件带有 Authenticode 签名，因此 Windows 会显示发布者名称，而不是警告来自未知发布者。

系统要求

  • Windows 10 1809 或更高版本，或 Windows Server 2019 或更高版本。仅支持 64 位：32 位进程读取的是被重定向的路径和注册表项，这会悄悄地产生错误的结果。
  • 无需安装 .NET。两个可执行文件都自带 .NET 运行时。
  • 更改任何内容都需要管理员权限。读取、搜索、快照和差异在没有管理员权限时也能工作，只是可见的条目会更少，工具会在顶部说明这一点，而不是假装列表就是整台计算机。

窗口只保留一个自己的文件：你离开时列表的布局，位于 %APPDATA%\BetterWindowsServices 下。快照会保存到你在 bws snapshot create 中指定的位置，未指定时则保存到当前目录。

程序使用英文界面。窗口会读取放在它旁边的语言文件 languages\gui.<code>.json，并根据 Windows 的语言选择，没有切换开关。因此翻译是一项无需重新生成就能加入的贡献：CONTRIBUTING.md 说明了方法。

杀毒软件与 EDR

这个工具做的是管理员对服务做的事，其中一部分正是安全软件所监视的行为。

它会停止和启动服务，可以结束服务背后的进程，并读取每个服务的安全描述符和所需特权。如果某个 EDR 把结束 svchost.exe 的进程标记出来，那它是在履行职责，而这里的强制停止看起来可能与之完全一样。

它不会做的事，便于你核对这一说法：它不会向任何进程注入任何内容，不会打包或混淆任何内容，不会安装服务或驱动程序，也不会留下任何运行中的内容，更不会建立任何网络连接。它以 GPL-3.0 开源，你可以自己构建这两个可执行文件。

如果你的策略需要排除项，请按文件而不是按文件夹排除这两个可执行文件。唯一值得与工具本身同样小心对待的是快照文件：它描述了整台计算机。

从源代码构建

.NET 10 SDK，在 Windows 上。

git clone {{repo}}
cd BetterWindowsServices
dotnet build BetterWindowsServices.slnx -c Release
dotnet test BetterWindowsServices.slnx -c Release

有些测试会读取它所运行的计算机上的真实服务控制管理器，并把这个工具的输出与 sc.exe 的输出进行比较。这些测试是只读的。发布版本所带的单文件可执行文件来自下面这两次发布，每次都生成一个内含运行时的文件：

dotnet publish src/Bws.Cli/Bws.Cli.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
dotnet publish src/Bws.Gui/Bws.Gui.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true

它们会以 bws.exe 和 BetterWindowsServices.exe 的名称出现在各项目的 bin/Release/.../win-x64/publish/ 下。旁边的 .pdb 文件是调试符号，运行时并不需要它们。
